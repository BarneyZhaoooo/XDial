XDial 隐私政策

更新于 2026 年 11 月 20 日 · 适用于 XDial iPhone、Mac 商店版和 Apple TV 版

XDial 是一款网络分流工具，由 XD Entertainment Pte Ltd 发布。它在本机按你设置的场景和规则转发网络流量。iPhone 版使用系统 VPN 扩展，Mac 商店版使用系统网络扩展。

客户端与公司网关分别处理哪些信息

  • XDial 客户端不含统计、广告或追踪 SDK。企业版包括公司维护的场景和规则。公司 VPN 线路使用员工自己的凭据，网关负责验证账号和接入权限。
  • 使用公司 VPN 时，公司网关会收到认证所需的信息、协议使用的设备信息和经该线路转发的流量。网关可以看到连接元数据，端到端加密会影响可见内容。若需了解所在单位的网关日志、保留期限或行使隐私权利，请通过单位既有的内部 IT 渠道联系。

保存在你设备上的信息

  • 线路、场景、规则和订阅等配置只保存在你的设备上；线路密码等凭据保存在系统钥匙串中。
  • 在 iPhone 和 Mac 上，为了按网络自动选择场景，XDial 会在本机读取当前 Wi‑Fi 名称，不会发送到任何地方。
  • 灵动岛和实时活动里显示的网速只在本机计算。

XDial 自己发出的网络请求

  • 你的流量：按你的配置直连，或发往你配置的线路服务器（例如所在单位的 VPN）。这些服务器由其运营者管理，适用其运营者的隐私政策。
  • 判断出口地区：配置了按出口地区选择场景时，XDial 可访问 Apple（gspe1-ssl.ls.apple.com）和 Cloudflare（/cdn-cgi/trace）的公开接口，读取当前网络出口所在的国家或地区。
  • 连接自检：连接后会访问 Google、Apple 和 Cloudflare 的公开测试地址，确认网络和分流是否生效。
  • 规则与订阅更新：从你配置的规则集和订阅地址下载更新。

连接你配置的远端服务时，该服务会收到建立连接所需的信息。例如，AnyConnect 服务器可收到凭据、设备名称、网卡地址和协议使用的设备标识。Tailscale 控制服务器可收到设备名称、节点公钥等注册节点所需的信息。请使用你信任的服务器或订阅。

iPhone 的 DNS 和网络检测

  • 通过本地 VPN 解析域名时，默认使用 Cloudflare 公共 DNS（1.1.1.1，未加密的 UDP）。通过 AnyConnect 解析的名称可发往 VPN 提供的 DNS，Tailscale 名称由其解析服务处理。相应的 DNS 提供方可以看到交给它的域名查询。
  • 连接时，XDial 可以访问 Amazon（checkip.amazonaws.com）或 Cloudflare 来查看线路的出口 IP。连接自检使用 Cloudflare 和 Apple 的测试地址，必要时使用阿里云的公共地址（223.5.5.5）。启用自动节点测速的线路还会定期访问 Google（www.gstatic.com）或配置指定的测速地址。
  • 按出口地区选择场景需要预置地区映射。iPhone 企业预置含有地区映射。使用该功能时，Apple 或 Cloudflare 可收到查询。
  • 这些服务会看到连接的来源 IP，可能是代理线路的出口。XDial 的连通性探测不会附带线路凭据。下载规则或订阅时，提供方会收到你配置的完整地址，包括地址中已有的访问令牌、用户名或密码。
  • 连接记录和诊断可包含出口 IP 等信息，保存在设备上。你可以主动导出或分享给自己选定的接收方。向公开问题区反馈时，请先移除密码、订阅地址和能识别你或所在网络的内容。

Mac 商店版的网络请求和权限

  • 连接期间，直连域名交给 Mac 的本地 DNS。走代理的域名通过该代理向 Cloudflare（1.1.1.1）发起加密 DNS 查询。查找代理服务器自身的域名时使用阿里公共加密 DNS（223.5.5.5）。AnyConnect 使用 VPN 提供的 DNS，Tailscale 名称在本机解析。
  • 每次连接会与 Cloudflare 和 Google 公共 DNS 做 TLS 握手，以检查连通性。当前场景的线路会通过 www.gstatic.com 或线路组指定的地址测延迟，断开状态下也可能测一次。订阅和 Tailscale 线路还可能访问 checkip.amazonaws.com 取得出口 IP。
  • 订阅按你设定的间隔刷新，默认每天一次。连接时缺少规则缓存或缓存已超过一天，会重新下载规则。提供方能看到请求的完整地址，包括地址中携带的访问令牌等凭据。
  • 使用 AnyConnect 时，你配置的 VPN 服务器会收到电脑名称、系统名称及版本、硬件标识和网卡 MAC 地址。使用 Tailscale 时，其控制服务器会收到随机生成的设备名和节点注册信息。Mac 商店版由 App Store 提供更新。

如果你要按 Wi-Fi 名称自动切换场景，Mac 版可在你点击相关设置时请求 macOS 的「使用期间」定位权限，以读取当前 Wi-Fi 名称。名称只在本机与场景设置比对。你也可以手动选择场景。

查询一条已连接线路的公网 IPv4 地址时，Mac 版可经该线路访问 Cloudflare 或腾讯（r.inews.qq.com/api/ip2city）。被访问的服务能看到这条线路的出口 IP。XDial 从腾讯的响应中读取 IP 地址；这项探测不会发送 Wi-Fi 名称或设备定位坐标，也不会读取响应中的城市。

Apple TV 的网络请求

你通过遥控器选择场景。客户端不按地区或 Wi-Fi 名称切换场景，也不为此请求定位。连接时，默认域名查询使用 Cloudflare 公共 DNS（1.1.1.1，未加密）；AnyConnect 可使用 VPN 提供的 DNS，Tailscale 按自身的方式解析名称。网络检测可访问 Cloudflare、Apple、阿里公共 DNS 和 Google 的测速地址；检查线路出口可访问 Amazon 或 Cloudflare。这些服务可看到连接来源 IP。

配置 AnyConnect 后，VPN 网关可收到设备名、设备类型、网卡地址及协议使用的设备标识。启用 Tailscale 后，设备信息发往对应的控制服务。规则和订阅提供方可收到配置中给出的完整请求地址。登录公司 VPN 时，员工凭据由网关验证。

儿童

XDial 企业版供获授权的员工和设备使用。

XDial Privacy Policy

Updated November 20, 2026 · Applies to XDial for iPhone, Mac App Store and Apple TV

XDial is a network routing tool published by XD Entertainment Pte Ltd. It routes traffic on your device according to your scenarios and rules. The iPhone app uses the system VPN extension, and the Mac App Store app uses a system network extension.

What the client and your company gateway process

  • The XDial client contains no analytics, advertising or tracking SDKs. The enterprise edition includes company-managed routing rules and scenarios. Company VPN lines use the employee’s credentials. The gateway verifies the account and its access rights.
  • When you use a company VPN, its gateway receives authentication and device information required by the protocol and traffic routed through that gateway. It can see connection metadata. End-to-end encryption affects what content is visible. Contact your organization through its internal IT channel for gateway logging practices, retention periods or privacy requests.

Information kept on your device

  • Lines, scenarios, rules and subscriptions are stored only on your device; credentials such as line passwords are kept in the system Keychain.
  • On iPhone and Mac, XDial can read the Wi‑Fi name on the device to pick a scenario for the current network. It is never sent anywhere.
  • The speeds shown in the Dynamic Island and Live Activity are computed on the device.

Network requests XDial makes

  • Your traffic goes directly or to the line servers you configured (for example your organization's VPN). Those servers are run by their operators, whose privacy policies apply.
  • Exit region: when configured to choose a scenario by exit region, XDial can query public endpoints of Apple (gspe1-ssl.ls.apple.com) and Cloudflare (/cdn-cgi/trace) to learn the country or region of the current network exit.
  • Connection self-check: after connecting, XDial requests public test URLs from Google, Apple and Cloudflare to confirm that the network and routing work.
  • Rule and subscription updates are downloaded from the addresses you configured.

When connecting to a remote service you configure, that service receives the information its protocol needs. For example, an AnyConnect server may receive credentials, the device name, a network interface address and a device identifier. A Tailscale control server may receive the device name, node public key and other node registration information. Choose servers and subscriptions you trust.

DNS and network checks on iPhone

  • For name resolution through the local VPN, the default is Cloudflare public DNS (1.1.1.1, unencrypted UDP). Names resolved through AnyConnect may go to the DNS server supplied by that VPN. Tailscale names use its resolver. The respective DNS provider can see the names sent to it.
  • When connecting, XDial may check a line’s public IP address with Amazon (checkip.amazonaws.com) or Cloudflare. Connectivity tests use Cloudflare and Apple test addresses and may fall back to an Alibaba Cloud public address (223.5.5.5). Lines that automatically measure node latency periodically reach Google (www.gstatic.com) or the test address in your configuration.
  • Exit-region selection requires a preset with region mappings. The iPhone enterprise preset includes these mappings. Apple or Cloudflare may receive region queries when this feature is in use.
  • These services can see the source IP of the connection, which may be your proxy’s exit address. Connectivity tests do not include line credentials. When a rule or subscription is downloaded, its provider receives the configured URL, including any token, username or password already in that URL.
  • Connection history and diagnostics, which may contain exit IP addresses, stay on your device. You can export or share them with a recipient you select. Remove passwords, subscription URLs and information identifying you or your network before posting in a public issue.

Network requests and permissions in the Mac App Store version

  • While connected, the Mac uses its local DNS resolver for direct connections. For proxied connections it sends encrypted DNS queries through the proxy to Cloudflare (1.1.1.1). It uses Alibaba encrypted DNS (223.5.5.5) to look up the proxy server itself. AnyConnect uses the DNS provided by the VPN. Tailscale names are resolved locally.
  • On each connection the app performs TLS handshakes with Cloudflare and Google Public DNS to check connectivity. Lines in the active scenario may contact www.gstatic.com or the line group's test address to measure latency, including once while disconnected. Subscription and Tailscale lines may also contact checkip.amazonaws.com to look up their exit IP.
  • Subscriptions refresh at the interval you set, daily by default. On connection the app downloads rule files if the cached copy is missing or more than a day old. The provider receives the full URL, including any credentials such as access tokens embedded in it.
  • When you use AnyConnect, your VPN server receives your computer name, OS name and version, hardware identifier and network adapter's MAC address. With Tailscale, the control server receives a randomly generated device name and node registration details. Updates to this edition are delivered by the Mac App Store.

If you want to switch scenarios by Wi-Fi name, the Mac app can request macOS location permission while in use when you choose the relevant setting. This lets it read the current Wi-Fi name and match it against your scenarios on the Mac. You can also choose a scenario manually.

When checking a connected line’s public IPv4 address, the Mac app may contact Cloudflare or Tencent (r.inews.qq.com/api/ip2city) through that line. The service sees the line’s exit IP address. XDial reads the IP address from Tencent’s response. This probe does not send the Wi-Fi name or device coordinates. It does not read the city from the response.

Network requests on Apple TV

You choose a scenario with the remote. The client does not select scenarios by region or Wi-Fi name and does not request location for this purpose. While connected, default DNS queries go to Cloudflare public DNS (1.1.1.1, unencrypted). AnyConnect may use the VPN's DNS server and Tailscale resolves its own names. Connectivity and latency checks may contact Cloudflare, Apple, Alibaba public DNS and Google test addresses. A line's exit IP may be checked with Amazon or Cloudflare. The services contacted can see the source IP.

An AnyConnect gateway can receive the device name, device type, interface address and protocol-specific device identifier. A configured Tailscale control service receives node information. Rule and subscription providers receive the full URL in the configuration. When using a company VPN, the gateway authenticates the employee's credentials.

Children
